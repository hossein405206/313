# سایت حلقه شهید هادی ذوالفقاری

سایت موبایل‌محور مسجد امام رضا (ع) / حلقه شهید هادی ذوالفقاری با GitHub Pages و Google Apps Script.

## نسخهٔ آمادهٔ بازبینی

- نسخهٔ یکپارچهٔ انتشار: `5.18.0` (فرانت‌اند و Google Apps Script)
- همهٔ منابع محلی CSS/JavaScript از پارامتر کش `v=5.18.0` استفاده می‌کنند.
- `activities.html` گزارش‌های اردو با گالری چندعکسی را از رویدادهای خبری جدا نمایش می‌دهد.

## اتصال فعلی بک‌اند

تمام صفحات وب از لایه‌ی API مرکزی در `js/main.js` استفاده می‌کنند و endpoint فعلی این است:

`https://script.google.com/macros/s/AKfycbwQu_bIijvel7wu1898AZVlWMKavL00egnJc6-eTT3HiWxxjOo54-LKUblvLNLZOCO9/exec`

فقط `js/main.js` باید URL بک‌اند را نگه دارد؛ فایل‌های دیگر از `KanoonApp.api` استفاده می‌کنند و endpoint جداگانه ندارند.

## ساختار اصلی

- `index.html` — خانه و رویدادها
- `activities.html` — گزارش اردوها با چند عکس به‌ازای هر گزارش، به‌علاوهٔ فهرست رویدادها
- `schedule.html` — برنامه هفتگی
- `coach.html` — پنل مربیان
- `officials.html` — ورود مسئولین
- `attendance.html` — حضور و غیاب
- `supervision.html` — نظارت
- `login.html` / `register.html` / `profile.html` — ورود و پروفایل اعضا
- `js/main.js` — API مرکزی و منطق مشترک
- `js/coach.js` — منطق پنل مربیان
- `apps-script/Code.gs` — بک‌اند Google Apps Script

## ورود، دسترسی و امنیت

- ورود اعضا رایگان و بدون پیامک است: حساب جدید با نام، شماره همراه و گذرواژه ساخته می‌شود؛ دفعات بعد فقط شماره همراه و گذرواژه لازم است. گذرواژه به شکل هش ذخیره می‌شود، نه متن آشکار.
- حساب‌های قدیمی که هنوز گذرواژه ندارند، برای فعال‌سازی اولیه باید یک‌بار نام قبلاً ثبت‌شده را همراه شماره و گذرواژه وارد کنند؛ پس از آن نام ورودی معیار ورود نیست.
- برای اینکه GitHub Pages بتواند API را صدا بزند، Web App باید با `Execute as: Me` و `Who has access: Anyone` منتشر شود؛ این تنظیم به‌خودی‌خود شیت و پوشه Drive را عمومی نمی‌کند.
- اطلاعات مربی ارشد فقط در **Project Settings → Script Properties** با کلیدهای `MASTER_COACH_PHONE`، `MASTER_COACH_CODE` و اختیاری `MASTER_COACH_NAME` نگه‌داری می‌شود؛ نام نمایشی می‌تواند فارسی باشد.
- مربی ارشد مربیان را اضافه می‌کند. مربیان با مجوز «مدیریت مسئولین» می‌توانند مسئولین را ثبت و مدیریت کنند و هر مربی می‌تواند شماره یا رمز ورود خودش را تغییر دهد.
- انتقادها و پیشنهادها در شیت «بازخوردها» ثبت می‌شوند و داخل پنل مربیان در بخش «انتقاد و پیشنهاد اعضا» دیده می‌شوند.
- عکس پروفایل عضو در پوشه Drive پروژه ذخیره می‌شود و در جدول‌های رکورد بازی نمایش داده می‌شود.
- در نصب تازه، `setup()` برای مسئولین کدهای تصادفی و قوی می‌سازد و آن‌ها را در شیت «مسئولین» و خروجی تابع ثبت می‌کند؛ کدها را از شیت بردار و امن به مسئول مربوطه تحویل بده. اگر کدهای قدیمی `*-CHANGE-ME` در شیت مانده باشند، اجرای `setup()` آن‌ها را جایگزین می‌کند.
- برای نصب تازه، `setup()` را یک بار اجرا کن. برای همین سایتِ ازقبل‌راه‌اندازی‌شده، شیت «گزارش فعالیت‌ها» و ستون‌های لازم هنگام اولین درخواست به‌طور خودکار ساخته/هماهنگ می‌شوند؛ اجرای مجدد `setup()` برای این قابلیت لازم نیست.
- بعد از جایگزین‌کردن `apps-script/Code.gs`، نسخهٔ منتشرشده را از **Deploy → Manage deployments → Edit → New version → Deploy** به‌روز کن. از **New deployment** استفاده نکن، مگر آنکه URL جدید را در `js/main.js` هم جایگزین کنی. درخواست‌های دارای توکن اکنون از بدنهٔ POST استفاده می‌کنند تا توکن در نشانی درخواست قرار نگیرد. تغییر GitHub به‌تنهایی بک‌اند منتشرشده را به‌روز نمی‌کند.
- پس از Deploy، `?action=ping` را باز کن؛ نسخه باید `5.18.0` باشد.
