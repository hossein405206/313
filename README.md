# سایت حلقه شهید هادی ذوالفقاری

سایت موبایل‌محور مسجد امام رضا (ع) / حلقه شهید هادی ذوالفقاری با GitHub Pages و Google Apps Script.

## نسخهٔ آمادهٔ بازبینی

- لایهٔ طراحی مشترک `5.58.0`: یکپارچه‌سازی فوکوس صفحه‌کلید، محدودکردن عرض رسانه‌ها و کنترل‌های فرم، نمایش یکدست حالت غیرفعال و رعایت تنظیم کاهش حرکت سیستم‌عامل. نسخهٔ کش CSS مشترک در هر ۱۶ صفحهٔ HTML هماهنگ شد؛ این تغییر به انتشار Apps Script نیاز ندارد.

- نسخهٔ 5.53.0: بنر تایپوگرافی حلقه شهید هادی ذوالفقاری در ابتدای صفحهٔ خانه، با PNG محلی و حفظ نسبت تصویر اضافه شد. فایل در `images/file_00000000201881f49fb488b48378d04f.png` میزبانی می‌شود؛ تغییر صرفاً فرانت‌اند است و به انتشار Apps Script نیاز ندارد.

- نسخهٔ ۵.۵۲.۰: ورود مربی نشست مسئول اردو را پاک می‌کند تا پنل اردو-only به پنل مربی منتقل نشود؛ نمودار حضور مربیان مستقل از مجوز گزارش‌ها نمایش داده می‌شود. نسخهٔ بک‌اند مورد انتظار فعلی `4.30.0-camp-capacity-official-role` است؛ این تغییرات فرانت‌اند به انتشار Apps Script نیاز ندارند.

- فرانت‌اند: `5.53.0`
- نسخهٔ ۵.۴۳.۰: نشست اعضا بدون انقضای زمانی نگه داشته می‌شود، اما هر درخواست همچنان فعال‌بودن حساب را بررسی می‌کند؛ نشست مربیان و مسئولان همچنان ۱۲ ساعت اعتبار دارد. قبل از غیرفعال‌سازی حساب از حضور و غیاب، هشدار روشن نمایش داده می‌شود. برای فعال‌شدن منطق نشست، بک‌اند `4.25.0-jalali-date-limits` را در Apps Script با **New version** منتشر کن.
- نسخهٔ ۵.۴۰.۰: فرم افزودن عضو در حضور و غیاب فقط نام کامل می‌گیرد؛ شماره تلفن اختیاری است. بک‌اند نیز برای پذیرش عضو بدون شماره به `4.21.0-camps-attendance` ارتقا یافته است. پس از جایگزینی فایل Apps Script، انتشار نسخهٔ جدید لازم است.
- نسخهٔ ۵.۳۸.۰: نشست منقضی‌شدهٔ بازی کاربر را به ورود مجدد هدایت می‌کند؛ راهنمای لمس تکراری از صفحه بازی حذف شد؛ نسخه کش صفحات با `js/main.js` هماهنگ شد.
- بک‌اند داخل مخزن `4.32.0-legacy-account-guard`: در فعال‌سازی اولیهٔ حساب‌های قدیمی، اگر نام قابل تطبیق در رکورد موجود نباشد، سامانه دیگر اجازه نمی‌دهد هر فردی صرفاً با شماره همراه، گذرواژهٔ تازه برای آن حساب بسازد. در این حالت مربی باید اطلاعات حساب را حضوری بررسی و رکورد را اصلاح کند. این تغییر فقط پس از انتشار نسخهٔ جدید `apps-script/Code.gs` در Google Apps Script روی سایت زنده اعمال می‌شود.
- `activities.html` گزارش‌های اردو با گالری چندعکسی را از رویدادهای خبری جدا نمایش می‌دهد.
- نسخهٔ ۵.۳۰.۰: اصلاح درخواست‌های احراز‌شدهٔ POST، جداسازی رکورد هفتگی بازی از رکورد تاریخی، اعتبارسنجی سمت سرور برای حضور و غیاب و محدودیت ورودی‌های رویداد/اخطار.
- نسخهٔ ۵.۳۳.۰: تایپ مرحله‌ای متن حدیث در صفحهٔ اصلی هماهنگ با ورود اعضا، انتخاب مستقیم نقش مسئول حضور و غیاب/نظارت، و بهبود واکنش‌گرایی و دسترس‌پذیری پنل مربیان و مسئولین.
- نسخهٔ ۵.۳۱.۰: جلوگیری از ثبت ناقص حضور و غیاب، استفاده از تاریخ سرور تهران، و تکمیل محدودیت طول ورودی‌های حساب‌ها و ثبت‌نام حلقه.
- نسخهٔ ۵.۳۲.۰: افکت تایپ حدیث در صفحهٔ اصلی با صفحهٔ ورود هماهنگ شد؛ پنل مسئولین بازطراحی شد و ظاهر پنل مربیان بهبود یافت.
- بک‌اند ۴.۱۹.۰: حذف کلید امنیتی پیش‌فرض و توقف امن احراز هویت در صورت تنظیم‌نبودن کلید؛ برای فعال‌شدن اصلاحات، فایل Apps Script را جایگزین و با New version منتشر کن.
- فونت عربی حدیث از فایل محلی Amiri (Naskh) استفاده می‌کند؛ مجوز SIL OFL در `fonts/OFL-Amiri.txt` است.
- انتخاب تاریخ تولد در تقویم شمسی، تاریخ را بلافاصله در فیلد نمایش می‌دهد؛ بک‌اند برای ذخیره‌ی نهایی همچنان باید نسخه‌ی جدید Apps Script را Deploy کند.

### تغییرات نسخهٔ فعلی مخزن

- فرانت‌اند `5.51.0`: محدودکردن نمودار حضور به بخش مجاز گزارش‌های مربیان؛ نمودار از صفحه مسئول حضور و غیاب جدا است. محدودیت انتساب مسئولیت‌ها در بک‌اند اعمال می‌شود.
- بک‌اند داخل مخزن `4.31.0-official-role-limits`: برای مسئولیت‌های غیرنظارت یک مسئول فعال و برای نظارت حداکثر پنج مسئول فعال مجاز است. محدودیت در افزودن، ویرایش و فعال‌سازی مجدد سمت سرور کنترل می‌شود؛ پیام سایت سقف عددی را افشا نمی‌کند.
- برای فعال‌شدن قابلیت‌ها در سایت زنده، ابتدا `apps-script/Code.gs` را جایگزین و ذخیره کن، سپس تابع `setup()` را یک بار اجرا کن تا ستون ظرفیت و نقش «مسئول اردو» ساخته شود؛ کد CAMP تولیدشده را از خروجی تابع بردار و نگه دار. بعد Deployment فعلی را از **Manage deployments → Edit → New version → Deploy** منتشر کن. نسخهٔ `?action=ping` باید `4.30.0-camp-capacity-official-role` را برگرداند.
- پارامترهای `v=` فایل‌های CSS/JavaScript در هر ۱۶ فایل HTML به `5.51.0` هماهنگ شده‌اند.

- پس از بررسی تغییر، کد فایل را در پروژهٔ Google Apps Script جایگزین کن و از **Deploy → Manage deployments → Edit → New version → Deploy** منتشر کن؛ ساخت Deployment تازه لازم نیست.

## ورود، دسترسی و امنیت

- ورود اعضا رایگان و بدون پیامک است: حساب جدید با نام، شماره همراه و گذرواژه ساخته می‌شود؛ دفعات بعد فقط شماره همراه و گذرواژه لازم است. گذرواژه به شکل هش ذخیره می‌شود، نه متن آشکار.
- حساب‌های قدیمی که هنوز گذرواژه ندارند، برای فعال‌سازی اولیه باید یک‌بار نام قبلاً ثبت‌شده را همراه شماره و گذرواژه وارد کنند؛ پس از آن نام ورودی معیار ورود نیست.
- برای اینکه GitHub Pages بتواند API را صدا بزند، Web App باید با `Execute as: Me` و `Who has access: Anyone` منتشر شود؛ این تنظیم به‌خودی‌خود شیت و پوشه Drive را عمومی نمی‌کند.
- اطلاعات مربی ارشد فقط در **Project Settings → Script Properties** با کلیدهای `MASTER_COACH_PHONE`، `MASTER_COACH_CODE` و اختیاری `MASTER_COACH_NAME` نگه‌داری می‌شود؛ نام نمایشی می‌تواند فارسی باشد.
- مربی ارشد مربیان را اضافه می‌کند. مربیان با مجوز «مدیریت مسئولین» می‌توانند مسئولین را ثبت و مدیریت کنند و هر مربی می‌تواند شماره یا رمز ورود خودش را تغییر دهد.
- انتقادها و پیشنهادها در شیت «بازخوردها» ثبت می‌شوند و داخل پنل مربیان در بخش «انتقاد و پیشنهاد اعضا» دیده می‌شوند.
- عکس پروفایل عضو در پوشه Drive پروژه ذخیره می‌شود و در جدول‌های رکورد بازی نمایش داده می‌شود.
- در نصب تازه، `setup()` برای مسئولین کدهای تصادفی و قوی می‌سازد و آن‌ها را در شیت «مسئولین» و خروجی تابع ثبت می‌کند؛ کدها را از شیت بردار و امن به مسئول مربوطه تحویل بده. اگر کدهای قدیمی `*-CHANGE-ME` در شیت مانده باشند، اجرای `setup()` آن‌ها را جایگزین می‌کند.
- برای نصب تازه، `setup()` را یک بار اجرا کن. برای همین سایتِ ازقبل‌راه‌اندازی‌شده، شیت «گزارش فعالیت‌ها» و ستون‌های لازم هنگام اولین درخواست به‌طور خودکار ساخته/هماهنگ می‌شوند؛ اجرای مجدد `setup()` برای این قابلیت لازم نیست.
- بعد از جایگزین‌کردن `apps-script/Code.gs`، نسخهٔ منتشرشده را از **Deploy → Manage deployments → Edit → New version → Deploy** به‌روز کن. از **New deployment** استفاده نکن، مگر آنکه URL جدید را در `js/main.js` هم جایگزین کنی. درخواست‌های دارای توکن اکنون از بدنهٔ POST استفاده می‌کنند تا توکن در نشانی درخواست قرار نگیرد. تغییر GitHub به‌تنهایی بک‌اند منتشرشده را به‌روز نمی‌کند.
- پس از Deploy، `?action=ping` را باز کن؛ نسخه باید `4.29.0-attendance-member-history` باشد.

## نسخه و کش مرورگر

نسخهٔ فرانت‌اند در `js/main.js` و پارامتر `v=` تمام ارجاعات CSS/JavaScript در ۱۶ صفحهٔ HTML باید با هم هماهنگ باشد. هنگام تغییر فرانت‌اند، شمارهٔ نسخه را در همهٔ صفحه‌ها یکجا افزایش بده؛ این کار کش قدیمی مرورگر را دور می‌زند. نسخهٔ بک‌اند مستقل است و فقط پس از انتشار واقعی Google Apps Script باید در `js/main.js` و مستندات با پاسخ `?action=ping` هماهنگ شود.

## یادداشت انتشار ۵.۲۳.۰

- مسیر عضویت بازی با عملیات احراز‌شدهٔ `POST` هماهنگ شده است.
- ورود مالک در پنل مربیان گذرواژه را با هش ذخیره‌شدهٔ حساب عضو بررسی می‌کند؛ شمارهٔ مجاز مالک باید در Script Property با کلید `MASTER_COACH_PHONE` تنظیم شده باشد. شماره و گذرواژهٔ واقعی در کد منبع نگهداری نمی‌شوند.
- برای فعال‌شدن ورود مالک، فایل `apps-script/Code.gs` را در Apps Script جایگزین و به‌صورت **New version** منتشر کن. تا قبل از انتشار، نسخهٔ فعال وب‌اپ همچنان نسخهٔ قدیمی خواهد بود.
- فایل‌های HTML در نسخهٔ `5.23.0` از فونت‌های نصب‌شدهٔ دستگاه و fallbackهای محلی استفاده می‌کنند؛ ارجاع دارایی‌ها نیز برای پاک‌شدن کش مرورگر به‌روز شده است.
- در صفحهٔ ارتباطات، تصویر لوگوی گروه رسانه‌ای مهدی موعود از لینک Google Drive ارائه‌شده استفاده می‌شود. برای نمایش عمومی، دسترسی فایل باید روی «Anyone with the link / Viewer» باشد.
- تایپوگرافی از Estedad برای رابط کاربری و Aref Ruqaa برای نمایش نقل‌قول‌های دینی استفاده می‌کند. فایل‌های فونت به همراه مجوز آزادشان در پوشهٔ `fonts/` میزبانی می‌شوند و به Google Fonts یا CDN خارجی وابستگی ندارند.
- ثبت تاریخ تولد در بک‌اند ورودی‌های فارسی، عربی و لاتین و جداکننده‌های `/`، `-` و `.` را نرمال‌سازی و به قالب `yyyy/MM/dd` تبدیل می‌کند.


بهبود ریزتایپوگرافی تقویم شمسی و نگاشت وزن فونت‌ها در نسخهٔ فرانت‌اند `5.21.0` انجام شد.


در نسخهٔ فرانت‌اند `5.22.0` فایل‌های فونت به پوشهٔ `fonts/` منتقل شدند تا از دامنهٔ خود GitHub Pages بارگیری شوند.


در نسخهٔ `5.23.0` فونت تزئینی از متن حدیث و تیترهای اصلی کنار گذاشته شد؛ Estedad با وزن‌های مشخص برای خوانایی و سلسله‌مراتب تیترها استفاده می‌شود.

- نسخهٔ ۵.۴۳.۰: رفع خطای شمارش حضور اعضایی که فقط با نام اضافه شده‌اند؛ هر عضو بدون شماره با شناسهٔ مستقل خودش در حضور و غیاب ثبت می‌شود.


نسخهٔ فعلی فرانت‌اند در مخزن: `5.49.0` — نسخهٔ کد بک‌اند در مخزن: `4.29.0-attendance-member-history`.
آرشیو تاریخی حضوریاب از پنل مربیان با انتخاب تاریخ قابل مشاهده است. نمودار داشبورد سه روند حاضر/موجه/غیبت را برای هشت روز اخیر نشان می‌دهد.


## اصلاح نمودار حضور و غیاب ۵.۴۷.۷

- تاریخ رکوردهای حضور و غیاب پیش از تجمیع نمودار به قالب میلادی `yyyy-MM-dd` نرمال می‌شود؛ این کار مقدارهای تاریخ واقعی Google Sheets و رشته‌های ISO را یکسان پردازش می‌کند.
- پس از تغییر `apps-script/Code.gs`، نسخهٔ `4.26.0-attendance-chart-date-normalization` را در Google Apps Script با **Manage deployments → Edit → New version → Deploy** منتشر کن. تغییر مخزن به‌تنهایی بک‌اند زنده را تغییر نمی‌دهد.


## نسخهٔ بک‌اند ۴.۳۳.۰ — تأیید حضوری حساب‌های جدید

- ثبت‌نام خودکار دیگر حساب را فعال نمی‌کند؛ حساب تازه با وضعیت `pending` و `active=false` ذخیره می‌شود و نشست ورود دریافت نمی‌کند.
- ستون‌های `approvalStatus`، `approvedAt` و `approvedBy` به شیت «اعضا» اضافه می‌شوند؛ برای ایجاد ستون‌های جدید، پس از جایگزینی کد، تابع `setup()` را یک‌بار اجرا کن. داده‌های قدیمی با وضعیت خالی، در صورت فعال‌بودن، عضو تأییدشده محسوب می‌شوند.
- مسئول حضور و غیاب می‌تواند از صفحهٔ حضور و غیاب درخواست‌ها را ببیند و پس از بررسی حضوری تأیید یا رد کند. رد درخواست، حساب را غیرفعال نگه می‌دارد؛ ثبت دوباره با همان شماره به درخواست تازهٔ در انتظار تأیید تبدیل می‌شود.
- پس از جایگزینی `apps-script/Code.gs` و اجرای `setup()`، نسخه را از **Deploy → Manage deployments → Edit → New version → Deploy** منتشر کن. سپس `?action=ping` را بررسی کن؛ نسخه باید `4.33.0-member-approval` باشد.
- فرانت‌اند `js/main.js` به نسخهٔ بک‌اند جدید و صفحات ورود/حضور و غیاب به فایل‌های تغییرکرده هماهنگ شده‌اند. تغییرات گیت‌هاب به‌تنهایی روی وب‌اپ Google Apps Script اعمال نمی‌شوند.


## بک‌اند ۴.۳۴.۰ — حفاظت از ارسال رسید اردو

- ارسال رسید پرداخت دیگر فقط با دانستن شناسهٔ ثبت‌نام ممکن نیست. هنگام ثبت‌نام اردو، سرور یک مجوز تصادفی یک‌بارمصرف می‌سازد و فقط همان پاسخ اولیه آن را به مرورگر می‌دهد؛ پس از ثبت موفق رسید، مجوز در شیت باطل می‌شود.
- ستون `receiptUploadToken` به شیت «ثبت‌نام‌ها» اضافه شده است. قبل از انتشار این نسخه، کد جدید `apps-script/Code.gs` را جایگزین کن، `setup()` را یک بار اجرا کن تا ستون اضافه شود، سپس از **Manage deployments → Edit → New version → Deploy** منتشر کن.
- نسخهٔ پاسخ `?action=ping` باید `4.34.0-receipt-upload-guard` باشد. فرانت‌اند `5.60.0` مجوز یک‌بارمصرف را دریافت و همراه رسید ارسال می‌کند. تغییرات GitHub به‌تنهایی بک‌اند زنده را تغییر نمی‌دهد.


## نسخهٔ ۵.۸۱.۰ — پنل مستقل مسئول اردو و اصلاح رسیدها

- مسئول اردو اکنون از طریق camp-official.html وارد یک صفحهٔ مستقل می‌شود؛ نمودار حضور و غیاب و کد پنل مربیان در این صفحه بارگذاری نمی‌شوند. آدرس قدیمی coach.html?campOfficial=1 نیز بلافاصله به صفحهٔ مستقل هدایت می‌شود.
- علت فنی خطای listCampPaymentReceipts: فرانت‌اند این عملیات را با POST می‌فرستاد، اما نام عملیات در فهرست خواندن‌های احراز‌شدهٔ POST-only نبود؛ در نتیجه handlePost آن را به‌عنوان عملیات ناشناخته رد می‌کرد. این عملیات اکنون از مسیر POST به خواندن احراز‌شده هدایت می‌شود تا توکن در query string قرار نگیرد.
- نسخهٔ فرانت‌اند 5.81.0 و نسخهٔ بک‌اند 4.39.0-camp-receipts-post-only است. نسخهٔ بک‌اند انتظارشده در فرم اردوها و پنل مربیان نیز هماهنگ شده است.

### انتشار بک‌اند
1. فایل apps-script/Code.gs را در پروژهٔ Google Apps Script جایگزین و ذخیره کن.
2. اگر تغییرات ساختاری نسخهٔ 4.38.0 هنوز اجرا نشده‌اند، تابع setup() را یک بار اجرا کن؛ برای اصلاح مسیر POST به‌تنهایی تغییر شیت جدیدی لازم نیست.
3. از Deploy → Manage deployments → Edit → New version → Deploy نسخهٔ جدید را منتشر کن و آدرس Web App فعلی را حفظ کن.
4. درخواست ?action=ping باید نسخهٔ 4.39.0-camp-receipts-post-only را برگرداند. انتشار روی GitHub به‌تنهایی کد Google Apps Script زنده را تغییر نمی‌دهد.
