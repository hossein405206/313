# Backend جدید سایت 313

فایل `apps-script/Code.gs` بک‌اند Google Apps Script پروژه است.

## راه‌اندازی

### 1) Google Sheet
یک Google Sheet بساز و ID آن را بردار.

### 2) Google Drive
یک پوشه برای تصاویر رویدادها و فایل‌های ثبت‌نام بساز و ID پوشه را بردار.

### 3) Apps Script
داخل همان Google Sheet برو:

**Extensions → Apps Script**

محتوای `apps-script/Code.gs` را در فایل اصلی قرار بده. شناسه‌های Sheet و Drive در ابتدای فایل در `CFG` قرار دارند؛ فقط در صورت تغییر منابع آن‌ها را عوض کن.

### 4) تنظیم امن مالک اصلی
از بخش **Project Settings → Script Properties** این مقادیر را بساز:

- `MASTER_COACH_PHONE`: شماره مالک اصلی
- `MASTER_COACH_CODE`: یک کد محرمانه جدید و قوی
- `MASTER_COACH_NAME`: نام نمایشی مالک (اختیاری)

کد مالک نباید داخل مخزن GitHub یا فایل `Code.gs` قرار بگیرد. چون کد قبلی در نسخه‌های قدیمی مخزن وجود داشته، برای مالک یک کد جدید انتخاب کن.

### 5) راه‌اندازی اولیه
بعد از تنظیم Script Properties، تابع `setup()` را یک بار اجرا کن. این نسخه ستون‌های مربوط به درخواست عضویت را به شیت «اعضا» اضافه می‌کند و ستون‌های قدیمی را بر اساس نام سرستون‌ها نگه می‌دارد. قبل از اجرا، از Google Sheet یک نسخه پشتیبان بگیر.

این شیت‌ها ساخته می‌شوند:

- تنظیمات
- مربیان
- مسئولین
- اعضا
- رویدادها
- اردوها
- ثبت‌نام‌ها
- حضورغیاب
- اخطارها
- بازی

کدهای اولیه مسئولین را حتماً بعد از setup تغییر بده.

تصاویر رضایت‌نامه اردو در نسخه جدید به‌صورت خصوصی ذخیره می‌شوند؛ لینک آن‌ها فقط در پنل مالک نمایش داده می‌شود. بعد از پشتیبان‌گیری، تابع `secureLegacyConsentPhotos()` را یک بار از ویرایشگر Apps Script اجرا کن تا دسترسی عمومی لینک‌های قدیمی رضایت‌نامه‌ها هم برداشته شود. اگر تابع `failed` برگرداند، مجوزهای Drive را دستی بررسی کن.

### 6) Deploy
از Apps Script:

**Deploy → New deployment → Web app**

تنظیمات:

- Execute as: **Me**
- Who has access: **Anyone**

آدرس `/exec` را بردار.

### 7) اتصال سایت
اگر URL جدید با URL داخل `js/main.js` فرق دارد، مقدار `CONFIG.API_URL` را با URL جدید عوض کن.

## منطق دسترسی

### مربی
- مدیریت رویدادها و تصاویر Drive
- مشاهده ثبت‌نام‌ها
- تایید / رد ثبت‌نام
- مشاهده گزارش حضور و غیاب ماه جاری
- مشاهده اخطارهای ماه جاری
- تعیین جایزه بازی

### مسئول حضور و غیاب
- افزودن عضو
- حذف عضو از فهرست فعال
- ثبت فقط یک‌بار در روز
- سه وضعیت: حاضر / موجه / غیبت
- اطلاعات روزهای قبلی در Sheet باقی می‌ماند اما از پنل مسئول نمایش داده نمی‌شود

### مسئول نظارت
- ثبت مسئولیت
- انتخاب نام فرد
- ثبت دلیل اخطار
- مشاهده سوابق ماه جاری

### عضویت در حلقه
- درخواست عضویت از صفحه `circle-register.html` ارسال می‌شود.
- درخواست‌ها ابتدا در وضعیت «در انتظار بررسی» قرار می‌گیرند.
- فقط مالک اصلی از پنل مربیان می‌تواند درخواست را تأیید یا رد کند.
- بازی‌ها هم در سمت سایت و هم هنگام ذخیره رکورد در سرور، وضعیت عضویت تأییدشده را بررسی می‌کنند.
- حساب‌های قدیمی که به‌صورت خودکار از ورود ساخته شده‌اند، خودبه‌خود عضو محسوب نمی‌شوند؛ باید درخواستشان بررسی شود.

### بازی مار
- صفحه `snake.html` برای اعضای تأییدشده است.
- افکت صدای گاز به‌صورت برنامه‌ای ساخته می‌شود و فایل صوتی بیرونی ندارد.
- رکورد مار فعلاً فقط روی همان دستگاه ذخیره می‌شود و وارد جدول رکوردهای بازی هفتگی نمی‌شود.

### بازی
- رکوردها بر اساس هفته ذخیره می‌شوند
- هفته از جمعه شروع می‌شود
- بهترین رکورد هفته در جدول عمومی نمایش داده می‌شود
- مربی متن جایزه را تعیین می‌کند
- مقدار پیش‌فرض:
  **به بیشترین رکورد هفته جایزه داده می شود**


## Endpoint فعلی سایت

`https://script.google.com/macros/s/AKfycbzI6-Csz0Fk8qixHiWTYOHrCGJq8W-7X2lWID6n5qkQOSLYGXC6-Jwixs7Bf38PunC0/exec`

این همان Web App endpoint است که در `js/main.js` تنظیم شده است. برای انتشار نسخه جدید، Deployment فعلی را ویرایش کن و نسخه جدید را انتخاب کن؛ URL را تغییر نده.


### احراز هویت پیامکی
مسیرهای `generateLoginCode` و `verifyLoginCode` تا زمان اتصال واقعی سرویس ارسال پیامک غیرفعال‌اند. ورود فعلی سایت با نام و شماره همراه، مالکیت شماره را با پیامک تأیید نمی‌کند؛ برای استفاده عمومی، اتصال OTP واقعی باید پیش از انتشار نهایی انجام شود.
