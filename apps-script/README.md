# Backend جدید سایت 313

فایل `apps-script/Code.gs` بک‌اند Google Apps Script پروژه است.

## راه‌اندازی

### 1) Google Sheet
یک Google Sheet بساز و ID آن را بردار.

### 2) Google Drive
یک پوشه برای تصاویر رویدادها و فایل‌های ثبت‌نام بساز و ID پوشه را بردار.

### 3) Apps Script
داخل همان Google Sheet برو:

**Extensions → Apps Script**

محتوای `apps-script/Code.gs` را در فایل اصلی قرار بده و این دو مقدار را تنظیم کن:

```js
SPREADSHEET_ID: 'ID_SHEET',
DRIVE_FOLDER_ID: 'ID_FOLDER'
```

### 4) راه‌اندازی اولیه
تابع `setup()` را اجرا کن. این تابع شیت اعضا را هم برای گذرواژه هش‌شده و عکس پروفایل به‌روز می‌کند؛ اجرای مجدد، داده‌های موجود را بر اساس نام ستون‌ها حفظ می‌کند.

این شیت‌ها ساخته می‌شوند:

- تنظیمات
- مربیان
- مسئولین
- اعضا
- رویدادها
- گزارش فعالیت‌ها (گالری مستقل چندعکسی اردوها و برنامه‌ها)
- اردوها
- ثبت‌نام‌ها
- ثبت‌نام حلقه (اطلاعات عضویت و تماس اضطراری)
- حضورغیاب
- اخطارها
- بازی

کدهای اولیه مسئولین را حتماً بعد از setup تغییر بده.

**امنیت مربی ارشد:** اطلاعات ورود را فقط در `Project Settings → Script Properties` ذخیره کن: `MASTER_COACH_PHONE`، `MASTER_COACH_CODE` و اختیاری `MASTER_COACH_NAME`. نام نمایشی می‌تواند فارسی باشد. اطلاعات ورود واقعی نباید در فایل کد یا مخزن عمومی قرار بگیرد. پس از تنظیم یا تغییر ساختار شیت‌ها، `setup()` را اجرا کن.

**از `AUTH_SECRET` محافظت کن:** این کلید به‌صورت تصادفی توسط `setup()` ساخته می‌شود و هم برای نشست‌های امضاشده و هم برای بررسی هش گذرواژه‌ها استفاده می‌شود. پس از نصب، آن را حذف یا دستی تغییر نده؛ گم‌شدن کلید می‌تواند ورود حساب‌های فعلی را از کار بیندازد. کد به مقدار ثابت و قابل‌حدس fallback نمی‌کند.

**ثبت‌نام در حلقه و بازی:** اطلاعات عضویت در شیت جداگانه «ثبت‌نام حلقه» ذخیره می‌شود؛ ثبت‌نام در این فرم شرط ورود به بازی است و تکمیل پروفایل به‌تنهایی شرط بازی نیست. اجرای `setup()` شیت جدید را ایجاد می‌کند.

**ورود اعضا بدون پیامک:** عضو جدید با نام، شماره همراه و گذرواژه وارد می‌شود؛ ورودهای بعدی با شماره و گذرواژه است. گذرواژه به شکل هش‌شده ذخیره می‌شود. برای حساب‌های قدیمی بدون گذرواژه، ورود اول باید نام قبلی ثبت‌شده را هم داشته باشد؛ این کار فقط برای فعال‌سازی اولیه است.

**پنل مربیان:** مالک مربیان را اضافه می‌کند. مجوز «مدیریت مسئولین» اجازه ثبت/ویرایش مسئولین را می‌دهد. هر مربی می‌تواند از بخش «حساب کاربری من» شماره یا رمز ورود خودش را تغییر دهد. پیام‌های انتقاد و پیشنهاد در پنل مربیان و شیت «بازخوردها» قابل مشاهده‌اند. عکس پروفایل از صفحه پروفایل بارگذاری و در جدول‌های رکورد نمایش داده می‌شود.

### 5) Deploy

**برای نصب تازه:** از **Deploy → New deployment → Web app** استفاده کن و تنظیمات را این‌طور قرار بده:

- Execute as: **Me**
- Who has access: **Anyone**

آدرس `/exec` را بردار و در `js/main.js` قرار بده.

**برای سایت موجود:** یک Deployment جدید نساز. از **Deploy → Manage deployments → Edit → New version → Deploy** استفاده کن تا URL فعلی ثابت بماند. تغییر GitHub به‌تنهایی نسخهٔ منتشرشدهٔ Apps Script را به‌روز نمی‌کند.

### گزارش‌های اردو با چند عکس

- هر گزارش در شیت «گزارش فعالیت‌ها» یک ردیف دارد و شناسه‌های چند عکس در همان ردیف ذخیره می‌شوند.
- برای سایت موجود، شیت گزارش‌ها با اولین درخواست به‌طور خودکار ساخته می‌شود؛ نیازی به ساخت دستی آن نیست.
- هر گزارش بین ۱ تا ۱۰ عکس می‌پذیرد. تصویرهای آپلودشده در پوشهٔ Drive قرار می‌گیرند و برای نمایش در صفحهٔ عمومی باید اشتراک‌گذاری تصویری مجاز باشد.
- اگر ارسال بخشی از عکس‌ها یا ذخیرهٔ گزارش شکست بخورد، سیستم برای پاک‌سازی عکس‌های استفاده‌نشده تلاش می‌کند.

بعد از انتشار، `?action=ping` باید نسخهٔ `4.17.0-quality-hardening` را نشان بدهد. مقدار `APP_VERSION` در `Code.gs` مرجع نسخهٔ بک‌اند است؛ مقدار `BACKEND_VERSION` در `js/main.js` باید دقیقاً با آن برابر باشد. نسخهٔ cache-busting فایل‌های فرانت‌اند مستقل است. احراز هویت مسئولین با کد فقط از طریق POST انجام می‌شود؛ کد ورود را در URL قرار نده.

### کنترل رکورد بازی

هر دور بازی با `startGameSession` یک شناسهٔ تصادفی کوتاه‌عمر از سرور می‌گیرد. نشست در یک عملیات قفل‌شده فقط یک‌بار مصرف می‌شود، باید متعلق به همان عضو باشد و امتیاز با زمان سپری‌شده سازگار باشد. این کنترل برای رد رکوردهای آشکارا ناممکن است؛ چون بازی در مرورگر اجرا می‌شود، ضدتقلب کامل تضمین نمی‌شود.

### بررسی کیفیت کد

از ریشهٔ مخزن اجرا کن:

```sh
python scripts/validate_project.py
```

Workflow مربوط به این دستور، نحو فایل‌های JavaScript و Apps Script، سازگاری نام عملیات API، ارجاعات فایل‌های HTML/CSS/JavaScript و هماهنگی نسخه‌ها را در GitHub بررسی می‌کند. این آزمون ایستا است و جای تست واقعی Apps Script و Google Drive را نمی‌گیرد.

### 7) اتصال سایت
اگر URL جدید با URL داخل `js/main.js` فرق دارد، مقدار `CONFIG.API_URL` را با URL جدید عوض کن.

## منطق دسترسی

### مربی
- مدیریت رویدادها و تصاویر Drive
- مشاهده ثبت‌نام‌ها
- تایید / رد ثبت‌نام
- مشاهده گزارش حضور و غیاب ماه جاری
- مشاهده اخطارهای ماه جاری
- تعیین جایزه بازی

### مسئول حضور و غیاب
- افزودن عضو
- حذف عضو از فهرست فعال
- ثبت فقط یک‌بار در روز
- سه وضعیت: حاضر / موجه / غیبت
- اطلاعات روزهای قبلی در Sheet باقی می‌ماند اما از پنل مسئول نمایش داده نمی‌شود

### مسئول نظارت
- ثبت مسئولیت
- انتخاب نام فرد
- ثبت دلیل اخطار
- مشاهده سوابق ماه جاری

### بازی
- رکوردها بر اساس هفته ذخیره می‌شوند
- هفته از جمعه شروع می‌شود
- بهترین رکورد هفته در جدول عمومی نمایش داده می‌شود
- مربی متن جایزه را تعیین می‌کند
- مقدار پیش‌فرض:
  **به بیشترین رکورد هفته جایزه داده می شود**
