# Backend جدید سایت 313

فایل `apps-script/Code.gs` بک‌اند Google Apps Script پروژه است.

## راه‌اندازی

### 1) Google Sheet
یک Google Sheet بساز و ID آن را بردار. قبل از تغییر بک‌اند، از شیت فعلی یک نسخه پشتیبان بگیر.

### 2) Google Drive
یک پوشه برای تصاویر رویدادها و فایل‌های ثبت‌نام بساز و ID پوشه را بردار.

### 3) Apps Script
داخل همان Google Sheet برو:

**Extensions → Apps Script**

محتوای `apps-script/Code.gs` را در فایل اصلی قرار بده و فقط شناسه‌های فایل را در `CFG` تنظیم کن. اطلاعات مربی ارشد را داخل کد ننویس؛ آن‌ها را در **Project Settings → Script Properties** اضافه کن:

```text
MASTER_COACH_PHONE = شماره همراه مربی ارشد
MASTER_COACH_CODE = یک کد جدید و محرمانه با حداقل ۱۲ نویسه
MASTER_COACH_NAME = مربی ارشد
```

`SPREADSHEET_ID` و `DRIVE_FOLDER_ID` در `CFG` قرار می‌گیرند. هیچ رمز یا کد ورود را در مخزن عمومی قرار نده.

### 4) راه‌اندازی اولیه
تابع `setup()` را یک بار اجرا کن.

این شیت‌ها ساخته می‌شوند:

- تنظیمات
- مربیان
- مسئولین
- اعضا
- رویدادها
- اردوها
- ثبت‌نام‌ها
- حضورغیاب
- اخطارها
- بازی

کدهای اولیه مسئولین را حتماً بعد از setup تغییر بده. هنگام اجرای نسخه جدید، تابع `setup()` ردیف‌های قدیمی با نقش «master» را غیرفعال می‌کند و حساب مربی ارشد را با اطلاعات Script Properties هماهنگ می‌کند؛ قبل از اجرای آن از Google Sheet نسخه پشتیبان بگیر. برای باطل‌شدن نشست‌های قبلی پس از تعویض کد مربی ارشد، مقدار `AUTH_SECRET` را از Script Properties حذف کن و سپس `setup()` را اجرا کن تا کلید تازه ساخته شود؛ این کار همه نشست‌های فعال را از اعتبار می‌اندازد.

### 5) Deploy
از Apps Script:

**Deploy → New deployment → Web app**

تنظیمات:

- Execute as: **Me**
- Who has access: **Anyone**

آدرس `/exec` را بردار.

### 6) اتصال سایت
اگر URL جدید با URL داخل `js/main.js` فرق دارد، مقدار `CONFIG.API_URL` را با URL جدید عوض کن.

## نکته امنیتی مهم

این مخزن عمومی است و تاریخچه Git آن هم ممکن است نسخه‌های قبلی فایل‌ها را نگه دارد. کد مربی ارشد که قبلاً داخل کد قرار داشت باید محرمانه فرض نشود؛ یک کد تازه در Script Properties تنظیم کن و پس از انتشار، حساب/ردیف قدیمی مربی ارشد را غیرفعال کن. خاموش‌کردن `DEBUG` در `js/main.js` هم لاگ‌های عیب‌یابی مرورگر را کاهش می‌دهد.


### ورود اعضا و رمز عبور

- حساب جدید با نام، شماره همراه و رمز عبور حداقل ۸ نویسه‌ای ساخته می‌شود.
- ورود مجدد با شماره همراه و رمز عبور انجام می‌شود. نام خانوادگی تغییرکرده مانع ورود نمی‌شود و نام واردشده در صفحه ورود به‌تنهایی هویت حساب را تعیین نمی‌کند.
- رمز خام ذخیره نمی‌شود؛ برای هر حساب salt جداگانه و هش تکرارشونده ذخیره می‌شود.
- حساب‌های قدیمی که پیش از اضافه‌شدن رمز ساخته شده‌اند، عمداً با نام و شماره به‌تنهایی وارد نمی‌شوند. برای مهاجرت امن آن‌ها باید فرایند جداگانه‌ای با تأیید مسئول اجرا شود؛ تا آن زمان کاربر باید با مسئول سایت تماس بگیرد.
- شماره تلفن به‌تنهایی مالکیت خط را ثابت نمی‌کند. اگر نیاز به اثبات مالکیت شماره داری، باید سرویس پیامک واقعی وصل شود؛ endpoint تولید کد بدون ارسال پیامک از مسیر عمومی ورود حذف شده است.
- پس از انتشار نسخه جدید، مقدار `AUTH_SECRET` را در Script Properties عوض کن تا نشست‌های قدیمی باطل شوند.

### نقش‌ها و نشست‌ها

- چندین حساب عادی مربی پشتیبانی می‌شود؛ فقط حساب ویژه «مربی ارشد» یکتا است.
- درخواست‌های محافظت‌شده در سمت سرور فعال‌بودن حساب و نقش فعلی مربی/مسئول/عضو را دوباره بررسی می‌کنند؛ غیرفعال‌کردن حساب یا تغییر نقش، نشست قبلی را هم از کار می‌اندازد.
- قبل از اجرای `setup()` روی داده واقعی، از Google Sheet نسخه پشتیبان بگیر؛ مهاجرت سرستون‌ها ساختار شیت را بازنویسی می‌کند.

## منطق دسترسی

### مربی
- مدیریت رویدادها و تصاویر Drive
- مشاهده ثبت‌نام‌ها
- تایید / رد ثبت‌نام
- مشاهده گزارش حضور و غیاب ماه جاری
- مشاهده اخطارهای ماه جاری
- تعیین جایزه بازی

### مسئول حضور و غیاب
- افزودن عضو
- حذف عضو از فهرست فعال
- ثبت فقط یک‌بار در روز
- سه وضعیت: حاضر / موجه / غیبت
- اطلاعات روزهای قبلی در Sheet باقی می‌ماند اما از پنل مسئول نمایش داده نمی‌شود

### مسئول نظارت
- ثبت مسئولیت
- انتخاب نام فرد
- ثبت دلیل اخطار
- مشاهده سوابق ماه جاری

### بازی
- رکوردها بر اساس هفته ذخیره می‌شوند
- هفته از جمعه شروع می‌شود
- بهترین رکورد هفته در جدول عمومی نمایش داده می‌شود
- مربی متن جایزه را تعیین می‌کند
- مقدار پیش‌فرض:
  **به بیشترین رکورد هفته جایزه داده می شود**
